# 18. 前端产品化与演示工作区

## 1. 目标

本切片只处理用户可见的成品化问题，不改变预约、HITL、异常重排或会前会后的领域边界。目标是让主路径呈现为可交付的企业会议产品，而不是接口演示页：文案简洁、字段中文化、人员可选择、会议计划可信、会议室可用性可靠、消息内容符合日常协作语境。

## 2. 用户界面规则

- 智能编排首页只保留产品定位、输入区和六个高频入口；异常重排与会前会后作为独立业务入口，不再以调整/取消快捷语句占位。
- 用户主路径不展示 `Asia/Shanghai`、Java、API、Run ID、原始会议类型/房型枚举、人员 ID、版本号或测试说明。时区仍由内部契约统一为 `+08:00`，但不作为重复界面文案。
- 会议号、会议室编码、请求号和数据库主键不进入普通详情卡；管理员维护资源时仍可编辑业务必需的唯一房间编码。
- 会议类型、房型、状态、来源和参会角色使用集中映射的中文标签；未知值使用稳定的中文兜底。
- 手动创建和编辑会议时，用户直接输入参会人姓名（多个姓名以逗号、顿号、分号或换行分隔）；前端仅使用安全在职员工目录将精确姓名解析为用户 ID，浏览器不展示或要求输入数据库 ID。出现重名时要求补充“姓名（部门）”，无法唯一解析则不允许提交。
- `CONCURRENCY_TEST`、Day/Smoke/验收/并发/幂等等技术会议保留在数据库审计历史中，但普通会议与会前会后选择器默认过滤，不做破坏性删除。
- 消息中心同样过滤技术回归通知，并以同一集合计算侧栏未读数；通用通知标题在能够从正文取得会议名时转换为具体业务标题。
- 过期待确认草案的“返回原会话重新生成”必须触发真实的新 Run，而不是只修改路由。聊天区先写入明确的重新生成请求，再展示重新读取事实后的新方案；请求失败时展示可操作原因并把重试文本留在输入框。

## 3. 日历和会议室

- 周视图的日期顺序固定为周一至周日；纵向时间固定为 08:00 至次日 00:00，容器内部滚动且表头保持可见。
- 默认会议状态为“有效会议”，展示已确认与已完成记录，隐藏已取消记录；用户仍可显式查看已取消会议。
- 会议室时间轴在日期、起止时间、楼栋、楼层、容量、设备或房型变化后自动重新请求。
- 每轮会议室查询生成递增请求序号。旧日期的慢响应只能被丢弃，不能覆盖当前筛选；无响应槽位显示“待查询”，只有服务端明确返回 `available=false` 才显示“占用”。

## 4. 演示工作区数据

Flyway V10 在 `DEMO_DATA_ENABLED=true` 时新增 12 位在职员工、8 间会议空间、4 类设备、16 场跨部门会议以及面向在职用户的会议通知。会议覆盖研发、产品、销售、财务、人力、客户成功、法务与行政团队，标题、时间、会议室和参会人均使用虚构但业务可信的数据；会前议程与材料继续由真实会前会后功能维护，不在种子中预写可变业务状态。

演示数据只通过版本化迁移写入，不在前端硬编码，不删除既有并发/幂等/Smoke 历史，不重置命名卷。生产环境关闭演示数据开关时，V10 不写入这些记录。

## 5. 验收

1. 智能编排、待我确认、我的会议、会议室、消息中心和会前会后不再出现本方案列出的冗余或技术占位文案。
2. 我的会议周视图按周一至周日显示，时间轴包含 00:00 终点，会议类型为中文。
3. 创建/编辑会议和从会议室槽位创建会议时可直接输入多个姓名，并由在职员工目录唯一解析为参会人 ID；浏览器不输入或展示人员 ID，重名必须补充部门。
4. 切换会议室日期后自动出现对应日期的可用/占用状态，连续快速切换不会被旧请求回写。
5. 普通业务视图不出现 `CONCURRENCY_TEST`、Day、Smoke、验收等技术会议；数据库历史仍保留。
6. 张三和管理员消息中心可看到业务化的新消息；每位在职员工至少有一条与其部门下周会议关联的通知。
7. 普通详情和消息列表不展示会议号、房间编码、请求号、裸 `meetingId` 或英文 fixture 文案。
8. 桌面与 390×844 移动视口无横向溢出，控制台无错误；前端 type-check/build、Java 迁移与全量 verify、Compose 配置和现有 Smoke 回归通过。
