# 会议全生命周期 Golden Path

## 1. 目标

本演示以“支付网关 V2 上线架构评审”为固定业务故事，覆盖政策查询、多轮创建、HITL、改期继承、具体冲突说明、重规划、再次确认和取消。它是当前 Agent 的主验收目标，不以单条完美 Prompt 替代真实多轮对话。

固定时间基准为 `2026-08-14T10:00:00+08:00`，所有会议使用 `Asia/Shanghai`、30 分钟槽位和 `[start,end)`。

## 2. 演示脚本与期望结果

### 阶段 A：政策与创建

1. 用户：“上线架构评审对参会人和会议室有什么要求？”
   - Agent 查询并打开政策片段，回答带文档名、标题路径和 chunk/page 引用。
2. 用户：“25号下午帮我的小组安排支付网关 V2 上线架构评审。”
   - 系统默认补全为 `2026-08-25 12:00-18:00`；Java 解析当前部门 ACTIVE 成员并展示名单；时长缺失；设备/地点为 `UNSPECIFIED`，不能显示成“已明确”。
   - Run 进入 `WAITING_USER_INPUT`，不得提前查询忙闲/房间或创建草案。
3. 用户：“开90分钟，赵六请假不参加，要大屏和白板，最好2点开始，没别的要求。”
   - 增量删除赵六，保留其余已验证人员；时长 90 分钟；`LARGE_SCREEN`、`WHITEBOARD` 为硬约束；14:00 为软偏好；其他要求为 `CLOSED`。
   - 查询真实忙闲和房间，OR-Tools 给出最多 3 个候选；创建无占用草案并进入 `WAITING_CONFIRMATION`。
4. 用户 ACCEPT。
   - Java 最终校验后会议成为 `CONFIRMED`；正式会议室槽位立即占用，不等待其他参会人确认；系统只产生项目内通知/Outbox，不发送邮件。

### 阶段 B：改期与冲突解释

5. 用户：“把25号下午2点的支付网关 V2 上线架构评审改到27号同一时间，其他都不变。”
   - 目标选择条件是 25 日 14:00 和标题；目标时间是 27 日 14:00，两者不得混用。
   - Agent 唯一命中刚创建的会议，继承 90 分钟、人员、标题、类型和大屏/白板要求；目标窗口为 `2026-08-27 14:00-15:30`。
   - 忙闲/房间查询携带目标会议 ID，只排除该会议自身占用。
6. 测试数据在 27 日目标窗口制造李四会议冲突或原房间冲突。
   - Agent 不得只说“没有共同空闲时间”；必须显示请求窗口、90 分钟、李四、冲突起止时间和会议 ID，并给出有限的延后/换时建议。
   - 未得到用户授权时不得移动冲突会议，也不得自动放松必需人员或设备要求。
7. 用户：“那就按你推荐的最近可行时间。”
   - Agent 保留原硬约束，重新查询并规划；生成新的 RESCHEDULE 草案和新 confirmation token，展示 Before/After。
8. 用户 ACCEPT。
   - Java 原子替换原会议时间/房间/槽位，状态继续为 `CONFIRMED`。

### 阶段 C：取消

9. 用户：“取消刚才改期的支付网关 V2 上线架构评审。”
   - Agent 唯一识别目标会议，生成取消预览并进入 `WAITING_CONFIRMATION`；确认前不释放槽位。
10. 用户 ACCEPT。
    - Java 将会议改为 `CANCELLED` 并释放槽位；重复确认保持幂等。

## 3. 必测异常

- 目标日期/时刻匹配到多场会议：返回候选摘要并追问，不默认选第一场。
- 目标会议不存在或用户无管理权限：返回稳定目标不可用说明，不进行后续查询。
- 同一 meetingId 的原始人员/房间占用：通过鉴权后的 `excludeMeetingId` 排除；其他 meetingId 的冲突必须保留。
- 并发确认冲突：旧 token 失效，保留硬约束重规划，生成新草案后再次 HITL。
- 页面刷新：恢复 `requirementDraft`、候选/HITL 或 `unsatAnalysis`，不得丢失已经确认的需求。

## 4. 完成证据

完成本 Golden Path 必须同时具备：Python 回归测试、Java Tool 鉴权与排除测试、前端类型检查/构建、Compose 健康、公共 API 实际轨迹和真实浏览器页面检查。仅有前端静态页面或 fixture 固定成功不算完成。
