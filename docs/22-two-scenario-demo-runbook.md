# 双场景功能演示手册

本文用于 2026-08-15 的双场景演示。时区固定为 `Asia/Shanghai`，因此“下周三”应解析为 2026-08-19，“下午”应解析为 12:00–18:00。

## 1. 演示前检查

项目使用基础 Compose 启动，浏览器入口为 <http://localhost>。演示账号如下：

- 张三：`zhangsan / demo-password`
- 管理员：`admin / demo-password`

先执行只读检查：

```powershell
python scripts/demo-two-scenarios.py status
```

输出必须满足：

- `ready: true`；
- 李四有两场永久保留的会议：13:00–14:00 和 14:00–15:00；
- `sceneTwoRoom` 为启用状态的“研发楼小组讨论室”，容量为 4 且无设备标签；
- `residualDemoMeetings` 与 `inactiveDemoRooms` 均为空。

## 2. 场景 1：RAG、需求补全和并发冲突重规划

以张三登录，在智能编排中依次输入：

```text
接待重要用户能直接使用vip会议室吗
```

预期：进入 Policy Agent，回答 VIP 会议室适用条件，并展示可打开的知识引用。

新建编排后输入：

```text
帮我安排一次WeMe1.1新版本发布评审，帮我找间会议室
```

预期：一次性要求补充时间窗口、时长和必需参会者；此时 Trace 中不得出现 `search_available_rooms`。

继续输入：

```text
安排在下周三下午，由我们组内的人参加
```

预期：显示 2026-08-19 12:00–18:00；通过通讯录解析研发中心 5 名在职成员；只继续询问时长，其他要求保持可选。

继续输入：

```text
会议会开2个小时，需要大屏和白板，没别的要求了
```

预期：生成候选与待确认草案，不要接受。记下草案的会议室、开始时间和结束时间。

切换管理员账号，在“我的会议”手动创建会议：

- 标题：`演示并发占位：WeMe1.1`
- 类型：普通会议
- 会议室、开始时间、结束时间：与张三待确认草案完全相同
- 必需参会者：管理员本人

切回张三，接受原草案。预期：

- `confirm_booking` 被 Java 最终并发校验拒绝；
- Run 出现 `BOOKING_CONFLICT` 和 `REPLAN`；
- Agent 使用已解析的人员身份重新查询房间和忙闲事实，不因前序模型调用预算已经耗尽而失败；
- 对话明确回复“当前会议室已被占用，请切换其他的编排选项”，编排抽屉自动切换到“候选”页；
- 页面给出其他可用会议室优先的候选和新的待确认草案，用户可点击“使用此方案重新校验”切换方案。

如果录屏停顿导致确认令牌过期，在“待我确认”点击“返回原会话重新生成”。页面会在原会话中自动提交一条“原确认草案已过期”的新请求，创建新 Run、重新读取当前占用事实并给出新方案；它不会复用旧候选或旧确认令牌。若服务端基线已不可恢复，输入框会保留可再次提交的完整提示，不会无声跳转。

演示到此可拒绝新草案，避免再创建一场会议。管理员占位会议会被演示后清理脚本取消。

## 3. 场景 2：结构化无解、房间失效和异常重排

张三新建编排，输入：

```text
请在 2026 年 8 月 26 日 13:00 到 15:00 之间安排 60 分钟会议，我，李四，王五，赵六，没有设备要求
```

预期页面展示：

- 请求窗口：2026-08-26 13:00–15:00；
- 连续时长：60 分钟；
- 类别：`REQUIRED_AVAILABILITY`（页面文案为“必需参会者时间冲突”）；
- 李四的两段冲突：会议 198 的 13:00–14:00、会议 199 的 14:00–15:00；
- 最多两条有限放宽建议。

继续输入：

```text
那就改到27号上午9点到12点，其他不变
```

预期：保持 60 分钟时长和四名必需参会者，在 09:00–12:00 搜索窗口内生成 60 分钟草案。默认首选为容量恰好匹配且没有历史占用的“研发楼小组讨论室”；接受草案并记下会议室。

切换管理员账号，在“会议室”中停用该会议室，原因可填写：

```text
演示：会议室设备临时故障
```

预期：

- 原会议保持原房间、原时间和 `CONFIRMED`，不会自动移动；
- 同一事务只创建一张 `OPEN` 异常单；
- 只有发起人张三收到 `RESOURCE_UNAVAILABLE` 通知。

切回张三，进入“异常重排”，打开对应异常单，点击“在智能编排中详细处理”。页面会预填以下开头，并在后面自动附带异常单号和会议 ID；不要删除自动附带的上下文：

```text
处理我的会议室失效异常单。优先保持原时间、时长、参会人和设备要求不变。
```

发送预填文本。预期：Agent 读取目标会议事实、排除失效会议室、保持 60 分钟原时段和四名参会者，给出 `RESCHEDULE` HITL 草案。接受后会议换到新房间，异常单变为 `RESOLVED`。

## 4. 演示后清理

先预览将处理的对象：

```powershell
python scripts/demo-two-scenarios.py cleanup
```

确认后执行：

```powershell
python scripts/demo-two-scenarios.py cleanup --apply
python scripts/demo-two-scenarios.py status
```

清理行为：

- 取消场景 1 的 `WeMe1.1` 演示会议及管理员并发占位会议；
- 取消场景 2 在 8 月 27 日创建或重排后的会议；
- 恢复场景 2 中被停用的原会议室，包括异常单已经 `RESOLVED` 的情况；
- 把管理员与张三的演示通知统一标为已读，避免下次录屏从历史未读角标开始；
- 永久保留李四在 8 月 26 日的两场冲突会议。

“删除演示会议”按业务审计规则实现为正常取消：占用槽位会释放，但会议、Outbox、通知和异常单审计记录不会被物理删除。脚本不访问数据库、不删除 Docker 卷。
